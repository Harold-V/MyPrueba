# Plan — Deudas y fiados

> Spec: [../specs/deudas-fiados.md](../specs/deudas-fiados.md) · Constitution v1.1.0 · Status: approved in autopilot
> Hereda §0 de los planes anteriores.

## 0. Global Constraints

- `paymentMethod` gana `CREDIT` ("Fiado"): solo válido en ventas; exige `customerId`.
- Ventas y abonos guardan una copia del nombre del cliente (`customer_name`).
- Deuda = Σ total de ventas `CREDIT` del cliente − Σ abonos del cliente, en centavos.

## 2. Architecture

```text
customers  (nuevo) — directorio de clientes; API pública CustomerDirectory + evento CustomerDeleting
ledger     — fiados, abonos, cuentas por cobrar, balance de caja; escucha CustomerDeleting
```

**Decisión principal:** el cálculo de deudas vive en `ledger`, que ya tiene las ventas; `customers`
es solo un directorio. Para no crear un ciclo (customers → ledger → customers), `customers` publica
`CustomerDeleting` dentro de su transacción y `ledger` lo veta lanzando `customer_has_debt`.

## 3. Interfaces & contracts

```text
customers API: CustomerView(id, name, phone|null); CustomerDirectory.find(businessId, id)
               record CustomerDeleting(businessId, customerId)
GET/POST /api/customers · PUT/DELETE /api/customers/{id}
  Customer = {id, name, phone|null, note|null}; DELETE con deuda ≠ 0 → 409 customer_has_debt
SaleInput += customerId?; Sale += customerId|null, customerName|null
  paymentMethod=CREDIT sin customerId → 400 field customerId code required
POST /api/customer-payments {customerId, amount, paymentMethod, occurredAt?, note?}
  -> 201 Payment | 400 (amount: exceeds_debt; paymentMethod CREDIT: invalid_value) | 404 customer_not_found
GET/PUT/DELETE /api/customer-payments/{id}
Payment = {id, type:"PAYMENT", customerId|null, customerName, amount, paymentMethod, occurredAt, note|null}
GET /api/receivables -> {total, customers:[{customerId, name, phone, debt}]}   (deuda ≠ 0, mayor primero)
GET /api/customers/{id}/account -> {customer, debt, entries:[{id, type:SALE|PAYMENT, amount, description, occurredAt}]}
Balance += payments, receivable;  balance = sales(pagadas) + payments − expenses
Movement += customerName|null; type ∈ {SALE, EXPENSE, PAYMENT}; filtro `sales` incluye abonos
```

## 4. Data model

- **customers** — id, business_id, name, phone, note, timestamps.
- **sales** + customer_id (→ customers ON DELETE SET NULL), customer_name.
- **customer_payments** — id, business_id, customer_id (SET NULL), customer_name, amount_cents,
  payment_method, occurred_at, note, timestamps; índice (business_id, occurred_at).

## 5. Testing strategy

Integración contra SQLite real por criterio (`CustomerApiTest`, `ReceivablesApiTest`), aislamiento
A/B en clientes, fiados, abonos y cuentas; `verify()` sin ciclos; componentes para clientes, cuenta,
abono, venta fiada, movimientos y balance.
