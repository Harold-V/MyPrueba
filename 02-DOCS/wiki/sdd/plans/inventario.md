# Plan — Inventario

> Spec: [../specs/inventario.md](../specs/inventario.md) · Constitution: [../constitution.md](../constitution.md) v1.1.0 · Status: approved in autopilot
> Hereda §0 de [cuentas-y-negocio](cuentas-y-negocio.md#0-global-constraints) y
> [libro-ventas-gastos-balance](libro-ventas-gastos-balance.md#0-global-constraints).

## 0. Global Constraints

- Cantidades de stock: BD `BIGINT` en milésimas; JSON string `"2.5"`; pueden ser negativas en BD.
- Costo: BD `BIGINT` centavos, opcional; JSON string decimal o `null`.
- Ajustes: `quantity` > 0 para `PURCHASE` y `LOSS`; ≥ 0 para `COUNT`.
- La venta y el cambio de stock que provoca ocurren en **la misma transacción**.

## 1. Context & constraints

- Criterios que dan forma: stock baja/sube con venta, edición y borrado; diferencia al editar;
  negativo permitido; valor del inventario; aislamiento.
- Fuera de alcance: gasto automático, proveedores, lotes, bloqueo de venta.

## 2. Architecture

```text
ledger --(evento SaleItemsChanged, síncrono, misma transacción)--> inventory
inventory --(ProductCatalog.find / list)--> catalog
inventory --(CurrentBusiness)--> accounts
```

- **inventory** (nuevo módulo) — stock por producto, movimientos, ajustes, resumen.
- **ledger** — publica `SaleItemsChanged` con las cantidades por producto antes y después.
- **catalog** — gana el campo `cost` opcional y `ProductCatalog.list(businessId)`.

**Decisión principal:** el libro no conoce el inventario. Publica un evento de dominio (Spring
Modulith) y el inventario lo escucha con `@EventListener` síncrono, dentro de la transacción de la
venta: si falla el stock, falla la venta, y nunca quedan desincronizados. Un listener asíncrono
(`@ApplicationModuleListener`) desacoplaría más pero exigiría registro de publicaciones y daría
consistencia eventual, innecesaria con SQLite en un solo proceso.

## 3. Interfaces & contracts

```text
ledger API (público):
  record SaleItemsChanged(UUID businessId, UUID saleId, Kind kind,
                          Map<UUID,Long> before, Map<UUID,Long> after)   // productId → milésimas
  enum Kind { RECORDED, EDITED, DELETED }

catalog API:
  ProductView(id, name, priceCents, costCents|null)
  ProductCatalog.list(businessId) -> List<ProductView>

HTTP:
GET  /api/inventory?lowOnly=true|false
  -> 200 {summary:{tracked, lowStock, value}, items:[InventoryItem]}
InventoryItem = {productId, name, price, cost|null, tracked, stock|null, minStock|null, low}
PUT  /api/inventory/{productId} {tracked, initialStock?, minStock?}
  -> 200 InventoryItem | 400 | 404       (initialStock obligatorio al activar)
POST /api/inventory/{productId}/adjustments {type: PURCHASE|LOSS|COUNT, quantity, note?}
  -> 201 InventoryItem | 400 | 404 | 409 code=not_tracked
GET  /api/inventory/{productId}/movements -> 200 [StockMovement]  (máx. 100, recientes primero)
StockMovement = {type, change, stockAfter, note|null, occurredAt}
type ∈ {INITIAL, PURCHASE, LOSS, COUNT, SALE, SALE_EDIT, SALE_DELETE}
POST/PUT /api/products acepta `cost` opcional; Product = {id, name, price, cost|null}
```

## 4. Data model & flow

- **products** (+ `cost_cents BIGINT NULL`).
- **stock_items** — product_id (PK → products ON DELETE CASCADE), business_id, quantity_milli,
  min_milli NULL, tracked, updated_at.
- **stock_movements** — id, product_id (→ products ON DELETE CASCADE), business_id, type,
  change_milli, stock_after_milli, note, sale_id NULL, occurred_at, created_at.

Flujo de venta editada: el libro carga las líneas previas → guarda las nuevas → publica
`SaleItemsChanged(before, after)` → el inventario, por cada producto controlado con
`after − before ≠ 0`, aplica `−(after − before)` y escribe un movimiento.

## 5. Testing strategy

| Criterio | Nivel | Afirma |
|---|---|---|
| venta / edición / borrado / cambio de producto | integración | stock y movimientos |
| producto no controlado | integración | sin movimientos |
| entrada, pérdida, conteo (cambio −4) | integración | stock y `change` |
| stock bajo, negativo, valor | integración | `low`, `summary` |
| cantidades inválidas | integración | `errors[field]` |
| aislamiento A/B | integración | 404 y sin cambios |
| eventos dentro de la transacción | integración | venta inválida no mueve stock |
| `verify()` | unit | inventory → ledger, catalog, accounts sin ciclos |
| pantallas inventario, costo, aviso en inicio, stock en venta | componente | flujo y errores |
